    4. VAE — O cabo de guerra dentro da perda¶

    Como reproduzir

    python3 -m pip install -r requirements.txt
python3 docs/exercises/vae/code/main.py

    main.py baixa o MNIST na primeira execução (para code/data/, fora do git), treina o VAE com \(d = 16\) e com \(d = 2\) na CPU e regrava as figuras em figures/ e todos os números em code/results.json (≈ 75 s num M2). Cada modelo é construído logo depois de torch.manual_seed(42), e a divisão usa o gerador do enunciado. Rodando duas vezes, o results.json sai idêntico. Todo número citado neste relatório vem desse arquivo.

    Se o download falhar com CERTIFICATE_VERIFY_FAILED (Python do python.org no macOS), rode o Install Certificates.command da pasta do Python ou use SSL_CERT_FILE=$(python3 -m certifi) python3 docs/exercises/vae/code/main.py.

    Código — vae.py (modelo, perda, amostragem e treino) 
    """VAE em PyTorch (Exercícios 1 e 2).

O autograd calcula os gradientes; as partes específicas do VAE são escritas à mão:
  * a reparametrização  z = mu + sigma * eps,  eps ~ N(0, I);
  * o termo de reconstrução (BCE somada nos 784 pixels, média nas imagens);
  * o termo KL em forma fechada, KL(N(mu, sigma^2) || N(0, I));
  * a amostragem da priori, z ~ N(0, I), decodificada.
Nada vem de uma classe de VAE pronta nem de torch.distributions.
"""
import torch
import torch.nn.functional as F
from torch import nn

N_PIXELS = 784


class VAE(nn.Module):
    """Arquitetura do enunciado: 784 -> 512 -> 256 -> (mu, log sigma^2) em R^d -> 256 -> 512 -> 784."""

    def __init__(self, latent_dim):
        super().__init__()
        self.latent_dim = latent_dim
        self.encoder = nn.Sequential(
            nn.Linear(N_PIXELS, 512), nn.ReLU(),
            nn.Linear(512, 256), nn.ReLU(),
        )
        self.mu_head = nn.Linear(256, latent_dim)       # média de q(z|x)
        self.logvar_head = nn.Linear(256, latent_dim)   # log sigma^2 de q(z|x): qualquer real é válido
        self.decoder = nn.Sequential(
            nn.Linear(latent_dim, 256), nn.ReLU(),
            nn.Linear(256, 512), nn.ReLU(),
            nn.Linear(512, N_PIXELS), nn.Sigmoid(),     # cada pixel = probabilidade de estar "aceso"
        )

    def encode(self, x):
        h = self.encoder(x)
        return self.mu_head(h), self.logvar_head(h)

    def decode(self, z):
        return self.decoder(z)

    def forward(self, x, generator=None):
        mu, logvar = self.encode(x)
        z = reparameterize(mu, logvar, generator)
        return self.decode(z), mu, logvar


def reparameterize(mu, logvar, generator=None):
    """z = mu + sigma * eps. O sorteio fica em eps, que não depende dos parâmetros,
    então o gradiente passa por mu e por sigma = exp(logvar / 2)."""
    sigma = torch.exp(0.5 * logvar)
    eps = torch.randn(mu.shape, generator=generator, dtype=mu.dtype)
    return mu + sigma * eps


def reconstruction_term(x_hat, x):
    """-log p(x|z) com pixels Bernoulli: BCE SOMADA nos 784 pixels, dividida pelo nº de imagens."""
    return F.binary_cross_entropy(x_hat, x, reduction="sum") / x.shape[0]


def kl_term(mu, logvar):
    """KL(N(mu, diag sigma^2) || N(0, I)) em forma fechada, somada nas d dimensões,
    média nas imagens:  1/2 * sum_i (mu_i^2 + sigma_i^2 - 1 - log sigma_i^2)."""
    return 0.5 * torch.sum(mu.pow(2) + logvar.exp() - 1.0 - logvar) / mu.shape[0]


def kl_per_dimension(mu, logvar):
    """O mesmo KL, mas sem somar nas dimensões (média nas imagens): quanto cada dimensão "custa"."""
    return 0.5 * torch.mean(mu.pow(2) + logvar.exp() - 1.0 - logvar, dim=0)


@torch.no_grad()
def sample_prior(model, n):
    """n imagens decodificadas de z ~ N(0, I). Usa o gerador global: chame torch.manual_seed antes."""
    z = torch.randn(n, model.latent_dim)
    return model.decode(z)


def run_epoch(model, X, batch_size, optimizer=None, beta=1.0, generator=None):
    """Uma passada por X. Com optimizer, treina (lotes embaralhados); sem, só avalia.

    Devolve (reconstrução, KL) em nats por imagem: médias ponderadas pelo tamanho de cada lote,
    ou seja, a média sobre todas as imagens da passada.
    """
    training = optimizer is not None
    model.train(training)
    n = X.shape[0]
    order = torch.randperm(n) if training else torch.arange(n)
    rec_total = kl_total = 0.0
    with torch.set_grad_enabled(training):
        for start in range(0, n, batch_size):
            x = X[order[start:start + batch_size]]
            x_hat, mu, logvar = model(x, generator)
            rec = reconstruction_term(x_hat, x)
            kl = kl_term(mu, logvar)
            if training:
                loss = rec + beta * kl          # -ELBO do lote, por imagem
                optimizer.zero_grad()
                loss.backward()
                optimizer.step()
            rec_total += rec.item() * x.shape[0]
            kl_total += kl.item() * x.shape[0]
    return rec_total / n, kl_total / n


def evaluate(model, X, seed=0, batch_size=1000):
    """Reconstrução e KL num conjunto, com UM z sorteado por imagem (estimativa usual do ELBO).

    O ruído vem de um gerador próprio com seed fixa: a avaliação não mexe no gerador global
    (que embaralha os lotes do treino), e todas as avaliações usam o mesmo ruído.
    """
    return run_epoch(model, X, batch_size, generator=torch.Generator().manual_seed(seed))


def train(model, X_train, X_val, epochs=20, lr=1e-3, batch_size=128, beta=1.0):
    """Adam, lr 1e-3, lotes de 128. Registra os dois termos no treino (média da época) e na validação."""
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    hist = {"train_rec": [], "train_kl": [], "val_rec": [], "val_kl": []}
    hist["val_rec_epoch0"], hist["val_kl_epoch0"] = evaluate(model, X_val)  # antes de treinar
    for _ in range(epochs):
        rec, kl = run_epoch(model, X_train, batch_size, optimizer, beta)
        hist["train_rec"].append(rec)
        hist["train_kl"].append(kl)
        rec, kl = evaluate(model, X_val)
        hist["val_rec"].append(rec)
        hist["val_kl"].append(kl)
    return hist

    """MNIST com a divisão do enunciado: 50 000 treino / 10 000 validação / 10 000 teste (oficial)."""
from pathlib import Path

import torch
from torch.utils.data import random_split
from torchvision import datasets, transforms

DATA_DIR = Path(__file__).resolve().parent / "data"  # baixado na primeira execução; fora do git


def load_mnist():
    """Devolve as três matrizes (N, 784) com pixels em [0, 1] e os rótulos.

    A divisão é exatamente a do enunciado. Depois, em vez de passar imagem a imagem pelo
    ToTensor (lento), divido o tensor uint8 inteiro por 255, que é o que o ToTensor faz;
    o assert confere numa imagem que o resultado é idêntico.
    """
    train_full = datasets.MNIST(DATA_DIR, train=True, download=True, transform=transforms.ToTensor())
    test = datasets.MNIST(DATA_DIR, train=False, download=True, transform=transforms.ToTensor())
    train, val = random_split(train_full, [50_000, 10_000],
                              generator=torch.Generator().manual_seed(42))

    def as_matrix(images):
        return images.float().div(255.0).reshape(-1, 784)

    X_train = as_matrix(train_full.data[train.indices])
    X_val = as_matrix(train_full.data[val.indices])
    X_test = as_matrix(test.data)
    assert torch.equal(X_train[0], train[0][0].reshape(-1)), "diferente do ToTensor"
    return {
        "X_train": X_train, "y_train": train_full.targets[train.indices],
        "X_val": X_val, "y_val": train_full.targets[val.indices],
        "X_test": X_test, "y_test": test.targets,
    }

def to_builtin(obj):
    """Converte tensores e tipos do NumPy em tipos nativos para o JSON."""
    if isinstance(obj, dict):
        return {str(k): to_builtin(v) for k, v in obj.items()}
    if isinstance(obj, (list, tuple)):
        return [to_builtin(v) for v in obj]
    if isinstance(obj, torch.Tensor):
        return to_builtin(obj.tolist())
    if hasattr(obj, "item"):          # escalares do NumPy
        return obj.item()
    return obj


def main():
    t0 = time.time()
    torch.set_num_threads(4)          # a ordem das somas em ponto flutuante depende do nº de threads
    data = load_mnist()
    model16, ex1 = ex1_mnist.run(data)
    print(f"[Ex1] d=16: teste rec {ex1['test_reconstruction']:.2f} + KL {ex1['test_kl']:.2f} "
          f"= {ex1['test_neg_elbo']:.2f} nats ({time.time() - t0:.0f} s)")
    ex2 = ex2_latent2d.run(data, model16)
    print(f"[Ex2] d=2: teste rec {ex2['test_reconstruction']:.2f} + KL {ex2['test_kl']:.2f} "
          f"= {ex2['test_neg_elbo']:.2f} nats ({time.time() - t0:.0f} s)")
    out = Path(__file__).resolve().parent / "results.json"
    out.write_text(json.dumps(to_builtin({"exercise_1": ex1, "exercise_2": ex2}), indent=2,
                              ensure_ascii=False), encoding="utf-8")
    print(f"Resultados gravados em {out} ({time.time() - t0:.0f} s)")


if __name__ == "__main__":

    Código completo — ex1_mnist.py 
    """Exercício 1 — Um VAE no MNIST (d = 16)."""
import math
from pathlib import Path

import matplotlib.pyplot as plt
import numpy as np
import torch

from vae import VAE, evaluate, kl_per_dimension, reconstruction_term, sample_prior, train

FIG_DIR = Path(__file__).resolve().parent.parent / "figures"
LATENT_DIM = 16


def first_of_each_digit(y):
    """Índice da primeira imagem de cada dígito 0-9."""
    return [int((y == k).nonzero()[0]) for k in range(10)]


@torch.no_grad()
def aggregate_log_density(Z, mu, logvar, chunk=1000):
    """log q(z) da posteriori agregada q(z) = (1/N) sum_n N(z; mu_n, diag sigma_n^2), avaliada em cada linha de Z.

    Expande (z - mu)^2 / sigma^2 em produtos de matrizes para não montar um tensor N x M x d.
    """
    mu, var = mu.double(), logvar.double().exp()
    inv = 1.0 / var
    const = -0.5 * (torch.sum(mu.pow(2) * inv, dim=1) + torch.sum(var.log(), dim=1)
                    + mu.shape[1] * math.log(2 * math.pi))
    out = []
    for start in range(0, Z.shape[0], chunk):
        z = Z[start:start + chunk].double()
        quad = -0.5 * (z.pow(2) @ inv.T - 2 * z @ (mu * inv).T)
        out.append(torch.logsumexp(quad + const, dim=1) - math.log(mu.shape[0]))
    return torch.cat(out)


def bernoulli_entropy(p):
    """Entropia (nats) de cada pixel Bernoulli(p), somada na imagem: incerteza que o decodificador admite."""
    p = p.clamp(1e-7, 1 - 1e-7)
    return -(p * p.log() + (1 - p) * (1 - p).log()).sum(dim=1)


def gray_fraction(images):
    """Fração de pixels "indecisos", nem apagados nem acesos: valor em (0.1, 0.9)."""
    return float(((images > 0.1) & (images < 0.9)).float().mean())


def fig1_curves(hist):
    epochs = np.arange(1, len(hist["train_rec"]) + 1)
    fig, (a, b) = plt.subplots(1, 2, figsize=(12, 4.4))
    for ax, key, name in ((a, "rec", "Reconstrução (BCE)"), (b, "kl", "KL")):
        ax.plot(epochs, hist[f"train_{key}"], "o-", ms=3, c="tab:blue", label="treino (média da época)")
        ax.plot(epochs, hist[f"val_{key}"], "s-", ms=3, c="tab:orange", label="validação (fim da época)")
        ax.set_xlabel("Época")
        ax.set_ylabel(f"{name} (nats por imagem)")
        ax.set_xticks([1, 5, 10, 15, 20])
        ax.grid(alpha=0.3)
        ax.legend()
    a.set_title("(a) Reconstrução × época")
    a.set_ylim(75, 180)
    b.set_title(f"(b) KL × época (validação antes do treino: {hist['val_kl_epoch0']:.2f})")
    b.set_ylim(0, 22)
    fig.suptitle("Figura 1 — Os dois termos da perda, treino e validação (Exercício 1, d = 16)")
    fig.tight_layout()
    fig.savefig(FIG_DIR / "fig1_loss_terms.png", dpi=150)
    plt.close(fig)


def image_rows(rows, row_labels, col_labels, title, path, col_title=None):
    """Grade de imagens 28x28: uma linha por lista em rows."""
    n_rows, n_cols = len(rows), len(rows[0])
    fig, axes = plt.subplots(n_rows, n_cols, figsize=(1.25 * n_cols, 1.45 * n_rows + 0.6))
    axes = np.atleast_2d(axes)
    for r in range(n_rows):
        for c in range(n_cols):
            ax = axes[r, c]
            ax.imshow(rows[r][c].reshape(28, 28), cmap="gray_r", vmin=0, vmax=1)
            ax.set_xticks([])
            ax.set_yticks([])
            if r == 0:
                ax.set_title(col_labels[c], fontsize=9)
            if c == 0:
                ax.set_ylabel(row_labels[r], fontsize=9)
            if r == n_rows - 1 and col_title and c == n_cols // 2:
                ax.set_xlabel(col_title, fontsize=9)
    fig.suptitle(title)
    fig.tight_layout()
    fig.savefig(path, dpi=150)
    plt.close(fig)


def fig3_samples(images, n=8):
    grid = images.reshape(n, n, 28, 28).permute(0, 2, 1, 3).reshape(n * 28, n * 28)
    fig, ax = plt.subplots(figsize=(6.4, 6.8))
    ax.imshow(grid, cmap="gray_r", vmin=0, vmax=1)
    ax.set_xticks(np.arange(14, n * 28, 28), range(1, n + 1))
    ax.set_yticks(np.arange(14, n * 28, 28), range(1, n + 1))
    ax.set_xlabel("Coluna da grade")
    ax.set_ylabel("Linha da grade")
    ax.set_title("Figura 3 — 64 amostras de z ~ N(0, I) decodificadas\n(torch.manual_seed(0); d = 16)")
    fig.tight_layout()
    fig.savefig(FIG_DIR / "fig3_prior_samples.png", dpi=150)
    plt.close(fig)


def run(data):
    FIG_DIR.mkdir(exist_ok=True)
    X_train, X_val, X_test, y_test = data["X_train"], data["X_val"], data["X_test"], data["y_test"]

    # B/C — modelo e treino (a seed vem antes de construir o modelo)
    torch.manual_seed(42)
    model = VAE(LATENT_DIM)
    hist = train(model, X_train, X_val)
    fig1_curves(hist)

    # C — números finais no teste (só agora o teste é usado)
    test_rec, test_kl = evaluate(model, X_test)
    model.eval()
    with torch.no_grad():
        mu, logvar = model.encode(X_test)
        rec_from_mu = model.decode(mu)
        test_rec_mu = float(reconstruction_term(rec_from_mu, X_test))

    # D — reconstruções (decodificando mu) e amostras da priori
    idx = first_of_each_digit(y_test)
    image_rows([X_test[idx], rec_from_mu[idx]], ["original", "reconstrução\n(decodifica μ)"],
               [f"dígito {k}\n(teste #{i})" for k, i in enumerate(idx)],
               "Figura 2 — Primeira imagem de teste de cada dígito e sua reconstrução (d = 16)",
               FIG_DIR / "fig2_reconstructions.png")
    torch.manual_seed(0)
    samples = sample_prior(model, 64)
    fig3_samples(samples)

    # E — medidas de apoio à análise
    with torch.no_grad():
        kl_dims = kl_per_dimension(mu, logvar)
        var_mu = mu.var(dim=0)
        # (a) onde caem as amostras da priori: densidade da posteriori agregada (componentes = teste)
        torch.manual_seed(1)
        z_prior = torch.randn(10_000, LATENT_DIM)
        mu_v, logvar_v = model.encode(X_val)
        z_post = mu_v + torch.exp(0.5 * logvar_v) * torch.randn(mu_v.shape)  # 1 z por imagem de validação
        logq_prior = aggregate_log_density(z_prior, mu, logvar)
        logq_post = aggregate_log_density(z_post, mu, logvar)
        p1 = torch.quantile(logq_post, 0.01)
        # (b) o que o decodificador devolve: probabilidades por pixel, não imagens binárias
        many_samples = model.decode(z_prior)
    return model, {
        "latent_dim": LATENT_DIM,
        "history": hist,
        "test_reconstruction": test_rec, "test_kl": test_kl, "test_neg_elbo": test_rec + test_kl,
        "test_reconstruction_decoding_mu": test_rec_mu,
        "val_kl_first_epoch": hist["val_kl"][0], "val_kl_last_epoch": hist["val_kl"][-1],
        "figure2_test_indices": idx,
        "kl_per_dimension_test": kl_dims.tolist(),
        "active_units": int((var_mu > 0.01).sum()),
        "var_mu_per_dimension_test": var_mu.tolist(),
        "prior_holes": {
            "median_logq_prior_samples": float(logq_prior.median()),
            "median_logq_posterior_samples_val": float(logq_post.median()),
            "fraction_prior_below_p1_of_posterior": float((logq_prior < p1).float().mean()),
            "fraction_prior_below_median_of_posterior": float((logq_prior < logq_post.median()).float().mean()),
        },
        "blur": {
            "gray_fraction_real_test": gray_fraction(X_test),
            "gray_fraction_reconstructions_mu": gray_fraction(rec_from_mu),
            "gray_fraction_prior_samples": gray_fraction(many_samples),
            "bernoulli_entropy_reconstructions_mu": float(bernoulli_entropy(rec_from_mu).mean()),
            "bernoulli_entropy_prior_samples": float(bernoulli_entropy(many_samples).mean()),
        },
    }

    A — Carregue e divida os dados¶

    load_mnist() carrega o MNIST do torchvision com transforms.ToTensor() e chama random_split exatamente como no enunciado: 50 000 imagens de treino e 10 000 de validação, com generator=torch.Generator().manual_seed(42). As 10 000 imagens oficiais de teste são o conjunto de teste. Para não passar imagem por imagem pelo ToTensor, divido o tensor uint8 inteiro por 255, que é o que o ToTensor faz, e achato cada imagem num vetor de 784 pixels em \([0, 1]\). Um assert confere numa imagem que o resultado é idêntico ao do ToTensor.

    O teste só aparece depois do treino de cada modelo, para os números finais e as figuras pedidas sobre ele. Durante o treino, tudo que é registrado vem do treino e da validação. Não há decisões de treino a tomar: arquitetura, otimizador e orçamento são fixos.

    B — Construa o modelo¶

    Parte Camadas
    Codificador \(784 \to 512 \to 256\), ReLU depois de cada uma
    Cabeças duas lineares \(256 \to d\): uma para \(\boldsymbol\mu\), outra para \(\log\boldsymbol\sigma^2\)
    Decodificador \(d \to 256 \to 512 \to 784\), ReLU nas ocultas, sigmoide na saída

    com \(d = 16\). As partes específicas do VAE, todas em vae.py:

    • Reparametrização (reparameterize): \(\mathbf{z} = \boldsymbol\mu + \boldsymbol\sigma \odot \boldsymbol\varepsilon\), com \(\boldsymbol\varepsilon \sim \mathcal N(\mathbf 0, I)\) e \(\boldsymbol\sigma = \exp(\tfrac12\log\boldsymbol\sigma^2)\). O sorteio fica em \(\boldsymbol\varepsilon\), que não depende dos parâmetros, então o gradiente passa por \(\boldsymbol\mu\) e \(\boldsymbol\sigma\). A cabeça prevê \(\log\sigma^2\), que pode ser qualquer número real, em vez de \(\sigma\), que teria de ser positivo.
    • Reconstrução (reconstruction_term): F.binary_cross_entropy(x_hat, x, reduction="sum") dividido pelo número de imagens do lote. É a BCE somada nos 784 pixels, em média por imagem, ou seja, \(-\log p(\mathbf x \mid \mathbf z)\) com cada pixel Bernoulli.
    • KL em forma fechada (kl_term): \(\tfrac12\sum_{i=1}^{d}(\mu_i^2 + \sigma_i^2 - 1 - \log\sigma_i^2)\), média nas imagens. Ela sai de \(\mathrm{KL} = \mathbb E_q[\log q - \log p] = \sum_i\big(-\tfrac12\log\sigma_i^2 - \tfrac12 + \tfrac12(\mu_i^2 + \sigma_i^2)\big)\), porque \(\mathbb E_q[(z_i-\mu_i)^2/\sigma_i^2] = 1\) e \(\mathbb E_q[z_i^2] = \mu_i^2 + \sigma_i^2\).
    • Perda: \(L = \text{reconstrução} + \beta\cdot\text{KL}\), com \(\beta = 1\) e os dois termos em nats por imagem.
    • Amostragem (sample_prior): \(\mathbf z \sim \mathcal N(\mathbf 0, I)\) pelo gerador global, decodificado.

    C — Treine¶

    Adam com taxa \(10^{-3}\), lotes de 128, 20 épocas (train em vae.py). O treino registra a média de cada termo ao longo da época. A validação é medida ao fim de cada época, com um \(\mathbf z\) sorteado por imagem, como no ELBO. O ruído da avaliação vem de um gerador próprio, de seed fixa, para não mexer no gerador que embaralha os lotes. Também medi a validação antes da primeira época (época 0).

    E — Análise¶

    Por que o otimizador aceita pagar mais KL. No início, o codificador devolve \(\boldsymbol\mu \approx \mathbf 0\) e \(\log\boldsymbol\sigma^2 \approx \mathbf 0\) para qualquer imagem. O KL é quase zero (0.03 na época 0), mas \(\mathbf z\) não carrega nada sobre \(\mathbf x\), e o decodificador só pode chutar ~0.5 em todo pixel: a reconstrução vale 544.7 nats, praticamente \(784\ln 2 = 543.4\). O KL mede quanta informação sobre a imagem o código carrega, em nats. Cada nat gasto nele permite ao decodificador saber mais sobre a imagem e economizar muito mais em reconstrução. O otimizador minimiza a soma, então paga KL enquanto a troca compensa:

    • da época 0 para a 1 (validação), o KL subiu 12.6 nats e a reconstrução caiu 415 nats;
    • da época 1 para a 20, o KL subiu mais 6.5 nats e a reconstrução caiu mais 46.6 nats.

    A troca fica cada vez menos vantajosa, e a curva do KL achata. Com \(\beta = 1\), o equilíbrio é o ponto em que um nat a mais de KL só compraria um nat de reconstrução. O total cai o tempo todo porque cada nat de KL comprou vários de reconstrução.

    Por que a Figura 3 é pior que a Figura 2: dois motivos diferentes.

    1. Onde caem as amostras da priori. O decodificador foi treinado com códigos sorteados de \(q(\mathbf z \mid \mathbf x)\) das imagens de treino. A união deles, a posteriori agregada \(q(\mathbf z) = \frac1N\sum_n q(\mathbf z \mid \mathbf x_n)\), não preenche \(\mathcal N(\mathbf 0, I)\) por igual: tem aglomerados e buracos entre eles. Medi isso com \(q(\mathbf z)\) formada pelas 10 000 posterioris do teste. A densidade de \(q\) nas amostras da priori tem mediana \(\log q = -54.3\); em códigos de imagens reais de validação, \(-38.4\), um fator de \(e^{16}\). 82% das amostras da priori caem abaixo da densidade mediana de um código real, e 7.7% abaixo do percentil 1 (se a priori batesse com \(q\), seria 1%). Essas amostras caem onde o decodificador quase nunca treinou, e o que sai dali é uma mistura de dígitos, ou nenhum dígito. Das 16 dimensões, 5 ficaram inativas (KL 0.00, \(\mathrm{Var}(\mu_i) = 0.001\)): nelas a posteriori é a própria priori e não há descompasso. Ele está nas outras 11. A Figura 5 mostra o mesmo efeito em 2-D: no centro do plano, onde a priori é mais densa, há imagens apagadas que não são dígito nenhum.
    2. O que o decodificador devolve para um dado \(\mathbf z\). A sigmoide dá, para cada pixel, a probabilidade de estar aceso, ou seja, a média de \(p(\mathbf x \mid \mathbf z)\), e não uma imagem sorteada. Se um código é compatível com várias imagens, a saída que minimiza a BCE esperada é a média delas: onde elas discordam, o pixel fica cinza, e o resultado é borrado. Medi a fração de pixels "indecisos" (valor entre 0.1 e 0.9): 8.6% nas imagens reais de teste, 14.8% nas reconstruções e 17.0% em 10 000 amostras da priori. A entropia Bernoulli somada por imagem, que é a incerteza que o próprio decodificador admite, vai de 81.5 nats nas reconstruções a 91.5 nas amostras: códigos da priori são mais ambíguos, e a média sobre mais imagens diferentes borra mais.

    Por que decodificar \(\boldsymbol\mu\) na Figura 2. \(\boldsymbol\mu\) é o centro de \(q(\mathbf z \mid \mathbf x)\), o código que resume o que o modelo guardou de \(\mathbf x\). Sortear \(\mathbf z = \boldsymbol\mu + \boldsymbol\sigma\odot\boldsymbol\varepsilon\) empurra o código para um vizinho aleatório: cada execução daria uma imagem diferente, e em média pior. No teste, a reconstrução vale 76.89 nats decodificando \(\boldsymbol\mu\) contra 82.31 com um \(\mathbf z\) sorteado. O ruído da reparametrização serve ao treino: obriga códigos vizinhos a decodificar em imagens parecidas e torna o espaço latente contínuo. Para mostrar a reconstrução, ele só atrapalha.

def fig4_scatter(mu, y):
    fig, ax = plt.subplots(figsize=(8, 7))
    cmap = plt.get_cmap("tab10")
    order = torch.randperm(len(y), generator=torch.Generator().manual_seed(0))  # mistura a ordem de desenho
    m, yy = mu[order].numpy(), y[order].numpy()
    for k in range(10):
        ax.scatter([], [], s=25, color=cmap(k), label=f"{k}")
    ax.scatter(m[:, 0], m[:, 1], s=3, c=[cmap(k) for k in yy], alpha=0.6, linewidths=0)
    lim = GRID_Z[-1]
    ax.plot([-lim, lim, lim, -lim, -lim], [-lim, -lim, lim, lim, -lim], "k--", lw=1,
            label="região da Figura 5")
    ax.set_xlabel("$\\mu_1$")
    ax.set_ylabel("$\\mu_2$")
    ax.set_title("Figura 4 — μ das 10 000 imagens de teste, por dígito (d = 2)")
    ax.legend(title="Dígito", markerscale=1, fontsize=9, loc="upper left", bbox_to_anchor=(1.01, 1))
    ax.set_aspect("equal")
    ax.grid(alpha=0.3)
    fig.tight_layout()
    fig.savefig(FIG_DIR / "fig4_latent_scatter.png", dpi=150)
    plt.close(fig)


@torch.no_grad()
def fig5_plane(model):
    # linha 0 da imagem = maior z2, para a orientação bater com a Figura 4 (z2 cresce para cima)
    z1, z2 = np.meshgrid(GRID_Z, GRID_Z[::-1])
    Z = torch.tensor(np.column_stack([z1.ravel(), z2.ravel()]), dtype=torch.float32)
    imgs = model.decode(Z).reshape(GRID_N, GRID_N, 28, 28)
    tiled = imgs.permute(0, 2, 1, 3).reshape(GRID_N * 28, GRID_N * 28)
    fig, ax = plt.subplots(figsize=(9, 9.4))
    ax.imshow(tiled, cmap="gray_r", vmin=0, vmax=1)
    ticks = np.arange(14, GRID_N * 28, 28)
    labels = [f"{0.0 if abs(v) < 1e-9 else v:.2f}" for v in GRID_Z]   # evita "-0.00" no centro
    ax.set_xticks(ticks, labels, rotation=90, fontsize=7)
    ax.set_yticks(ticks, labels[::-1], fontsize=7)
    ax.set_xlabel("$z_1 = \\Phi^{-1}(q)$,  q = 0.05 … 0.95")
    ax.set_ylabel("$z_2 = \\Phi^{-1}(q)$")
    ax.set_title("Figura 5 — Plano latente decodificado numa grade 15 × 15 de quantis (d = 2)")
    fig.tight_layout()
    fig.savefig(FIG_DIR / "fig5_latent_plane.png", dpi=150)
    plt.close(fig)


def to_grid_cell(z):
    """Posição (coluna, linha a partir do topo) de um ponto latente na grade da Figura 5, em unidades de célula."""
    step = (Q[-1] - Q[0]) / (GRID_N - 1)
    col = (norm.cdf(z[0]) - Q[0]) / step
    row_from_top = (GRID_N - 1) - (norm.cdf(z[1]) - Q[0]) / step
    return float(col) + 1, float(row_from_top) + 1   # 1-indexado, como se conta numa figura


def overlap_pairs(mu, y, k=15):
    """Pares de dígitos que se misturam em mu: para cada ponto, o dígito mais comum entre seus k vizinhos."""
    tree = cKDTree(mu.numpy())
    _, nn = tree.query(mu.numpy(), k=k + 1)
    neigh = y.numpy()[nn[:, 1:]]                       # exclui o próprio ponto
    majority = np.array([np.bincount(row, minlength=10).argmax() for row in neigh])
    yy = y.numpy()
    conf = np.zeros((10, 10), dtype=int)
    np.add.at(conf, (yy, majority), 1)
    pairs = sorted(((int(conf[i, j] + conf[j, i]), i, j) for i in range(10) for j in range(i + 1, 10)),
                   reverse=True)
    return conf, pairs, float(np.mean(majority == yy))


def run(data, model16):
    FIG_DIR.mkdir(exist_ok=True)
    X_train, X_val, X_test, y_test = data["X_train"], data["X_val"], data["X_test"], data["y_test"]

    # A — o mesmo modelo, só d = 2; mesmos dados, seed, beta e orçamento
    torch.manual_seed(42)
    model = VAE(LATENT_DIM)
    hist = train(model, X_train, X_val)
    test_rec, test_kl = evaluate(model, X_test)
    model.eval()
    model16.eval()

    with torch.no_grad():
        mu, logvar = model.encode(X_test)
        rec2 = model.decode(mu)
        mu16, _ = model16.encode(X_test)
        rec16 = model16.decode(mu16)

    # B — o conjunto de teste codificado
    fig4_scatter(mu, y_test)
    conf, pairs, knn_agree = overlap_pairs(mu, y_test)
    medians = {k: mu[y_test == k].median(dim=0).values.numpy() for k in range(10)}

    # C — o plano decodificado na grade de quantis
    fig5_plane(model)

    # D — interpolação: pixels x latente (modelo d = 16 do Exercício 1)
    t = torch.linspace(0, 1, N_STEPS)
    xa, xb = X_test[INTERP_A], X_test[INTERP_B]
    pixel_row = (1 - t)[:, None] * xa + t[:, None] * xb
    with torch.no_grad():
        latent_row = model16.decode((1 - t)[:, None] * mu16[INTERP_A] + t[:, None] * mu16[INTERP_B])
    image_rows([pixel_row, latent_row],
               ["pixels\n(1−t)x_a + t x_b", "latente, d = 16\ndecodifica\n(1−t)μ_a + t μ_b"],
               [f"t = {v:.2f}" for v in t.tolist()],
               f"Figura 6 — Interpolação entre o teste #{INTERP_A} (dígito {int(y_test[INTERP_A])}) "
               f"e o teste #{INTERP_B} (dígito {int(y_test[INTERP_B])})",
               FIG_DIR / "fig6_interpolation.png")

    # complementar — reconstruções d = 16 x d = 2 das mesmas imagens da Figura 2
    idx = first_of_each_digit(y_test)
    image_rows([X_test[idx], rec16[idx], rec2[idx]],
               ["original", "d = 16\n(decodifica μ)", "d = 2\n(decodifica μ)"],
               [f"dígito {k}" for k in range(10)],
               "Figura C1 (complementar) — As mesmas imagens reconstruídas com d = 16 e com d = 2",
               FIG_DIR / "fig_c1_d16_vs_d2.png")

    gray = lambda im: ((im > 0.1) & (im < 0.9)).float().mean(dim=1)  # noqa: E731
    return {
        "latent_dim": LATENT_DIM,
        "history": hist,
        "test_reconstruction": test_rec, "test_kl": test_kl, "test_neg_elbo": test_rec + test_kl,
        "val_kl_first_epoch": hist["val_kl"][0], "val_kl_last_epoch": hist["val_kl"][-1],
        "knn_majority_agrees_with_label": knn_agree,
        "top_overlapping_pairs": [{"digits": [i, j], "count": c} for c, i, j in pairs[:5]],
        "knn_confusion": conf.tolist(),
        "digit_medians_mu": {str(k): v.tolist() for k, v in medians.items()},
        "digit_medians_grid_cell_col_row": {str(k): to_grid_cell(v) for k, v in medians.items()},
        "grid_z": GRID_Z.tolist(),
        "interpolation": {
            "index_a": INTERP_A, "digit_a": int(y_test[INTERP_A]),
            "index_b": INTERP_B, "digit_b": int(y_test[INTERP_B]),
            "t": t.tolist(),
            "gray_fraction_pixel_row": gray(pixel_row).tolist(),
            "gray_fraction_latent_row": gray(latent_row).tolist(),
        },
    }

    C — O plano decodificado¶

    Como a priori é um produto de duas \(\mathcal N(0, 1)\) independentes e os pontos de cada eixo estão em quantis igualmente espaçados, entre dois vizinhos há sempre a mesma probabilidade (\(\Delta q = 0.9/14\)) em cada eixo. Por isso cada célula da grade tem a mesma massa \((\Delta q)^2\) da priori, enquanto um espaçamento linear daria células de massa muito maior no centro que nas bordas.

    E — Análise¶

    Quais dígitos se sobrepõem na Figura 4. O par mais misturado é 4 e 9. Para medir, olhei os 15 vizinhos mais próximos de cada ponto em \(\boldsymbol\mu\) e anotei o dígito mais comum entre eles: em 603 pontos de 4 ou de 9, o dígito mais comum é o outro (314 dos 4 e 289 dos 9). As medianas dos dois dígitos ficam a só 0.14 de distância, em \((0.34,\ 0.55)\) e \((0.46,\ 0.48)\). Os pares seguintes são 3–5 (362 pontos), 5–8 (157) e 3–8 (151). No total, em 20% dos pontos de teste os vizinhos são majoritariamente de outro dígito.

    Na Figura 5, as duas medianas caem nas linhas 4–5 a partir do topo e nas colunas 10–11 (\(z_2 \approx 0.5\)–\(0.7\), \(z_1 \approx 0.3\)–\(0.5\)). Andando para a direita nessas linhas, o 4 vira 9. Nas células da transição (\(z_1 \approx 0.16\)–\(0.33\)), a imagem é um 4 cujo traço superior esquerdo se curva até encostar no traço da direita, fechando a parte de cima. É um 4 de topo fechado, legível tanto como 4 quanto como 9. A diferença entre os dois dígitos é só fechar ou não esse laço. A transição 3–5 aparece nas linhas de baixo (\(z_2 \le -0.92\)): o 3 vira 5 quando o arco de cima se endireita na barra horizontal do 5, e a barriga de baixo, comum aos dois, não muda. O 5 aparece em dois lugares das Figuras 4 e 5, no alto à esquerda e embaixo junto ao 3. O plano não teve espaço para manter todos os 5 juntos.

    O que duas dimensões obrigam o modelo a jogar fora. Dois números por imagem precisam dizer qual dígito é e como ele foi escrito. Só a identidade custa \(\ln 10 = 2.3\) nats; o modelo de \(d = 2\) carrega 6.6 nats no total, então sobram ~4 nats para todo o estilo, contra 19 no modelo de \(d = 16\). A Figura 5 mostra o resultado:

    • O plano é gasto quase todo separando os dez dígitos.
    • Dentro da região de cada dígito sobra no máximo uma variação de estilo. Os 1 da direita variam só a inclinação, de verticais no alto a deitados embaixo, e os 0 da esquerda variam só a largura.
    • Espessura do traço, tamanho e traços particulares não têm coordenada onde morar e viram o protótipo da região.

    A Figura C1 confirma isso nas mesmas imagens da Figura 2:

    • Com \(d = 2\), cada uma vira um protótipo borrado, e o que era particular some: a cauda longa do 9 do teste #7 e o traço solto no topo do 5 do teste #8.
    • Nas mais ambíguas, até a identidade troca: o 3 vira um 8, o 4 vira um 9, o 5 vira um 4 e o 9 vira um 8.
    • Com \(d = 16\), todas continuam reconhecíveis.

    As duas linhas da Figura 6. A linha de cima (pixels) não passa por dígitos. Cada imagem do meio é um 2 e um 4 sobrepostos, cada um com intensidade parcial, como num cross-fade. A fração de pixels cinza (entre 0.1 e 0.9) sobe de 8.4% em \(t = 0\) para 27.0% em \(t = 0.44\) e volta a 7.8% em \(t = 1\). O conjunto das imagens de dígitos não é convexo no espaço de pixels: os traços dos dois dígitos estão em lugares diferentes, e a média tem dois traços pela metade em vez de um traço inteiro.

    A linha de baixo (latente, \(d = 16\)) passa por imagens que parecem dígitos: o 2 fecha a curva de baixo num laço, vira algo entre um 8 e um 6, depois um 9, e o laço se abre no 4. As imagens do meio ficam um pouco mais borradas, mas a fração de pixels cinza fica entre 14% e 23% o tempo todo, sem pico no meio. Cada imagem é um traço coerente, mesmo que não seja nem 2 nem 4: o caminho reto entre os dois códigos atravessa as regiões do 8, do 6 e do 9. Isso acontece porque o decodificador só sabe desenhar uma imagem por código e foi treinado com códigos de dígitos reais. Além disso, o termo KL junta os códigos de todos os dígitos numa região contínua em torno da origem, sem vãos largos entre eles, e o ruído da reparametrização obriga códigos vizinhos a decodificar em imagens parecidas. Por isso uma reta no espaço latente anda por cima da variedade dos dígitos, e a mesma reta no espaço de pixels corta por fora dela.
